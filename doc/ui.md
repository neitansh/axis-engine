# Интерфейс на RmlUi

Договор о том, как устроен интерфейс Axis поверх RmlUi: кто рисует, кто
думает, где лежит вид и как крейт делает меню своим. Formspec остаётся в
движке как наследие — для чужих модов и того, что ещё не переехало, — но
новые экраны на нём не пишутся.

**Сделано (к 13.09.2026):**

- библиотека в `lib/rmlui`, рендер на OpenGL 3 поверх драйвера Irrlicht,
  ввод, файлы, буфер обмена, курсор, текстовый ввод с IME; один `ui::Host`
  на весь запуск клиента (`ClientLauncher`), меню и экран загрузки делят его;
- главное меню на C++ (`src/client/menu`) с темой в `client/ui/menu`:
  старт с подтверждением выхода, одиночная игра (крейт → миры → создать /
  удалить / играть), сетевая игра (подбор матча с очередью и приглашениями из
  Discord, список серверов с избранным, откликом и прямым адресом),
  настройки с паритетом Lua-меню, «Об Axis»;
- экран загрузки (`menu::LoadScreen`) для всех состояний между меню и игрой;
  ошибка захода показывается на нём, «Назад»/Esc возвращают на тот экран
  меню, откуда уходили (`MainMenuData::screen`);
- дверца лаунчера (`menu::Launcher`): билеты, список серверов, логин,
  приглашения, присутствие; HTTP из меню — `menu::Net` поверх `httpfetch`;
- тема одета как сайт и лаунчер (словарь цветов в шапке `theme.rcss`);
  перевод текста темы — `[[English]]` в `.rml` через gettext;
- живая перезагрузка темы (F5) и отладчик RmlUi (F8);
- `main_menu_rml` включён по умолчанию; Lua-меню остаётся за
  `main_menu_rml = false`.

**Ещё нет — план для следующей сессии, по порядку:**

1. Тема крейта поверх темы движка: `depot/<crate>/menu` первым в
   `MainMenu::m_theme_dirs`; крейт кладёт свой `start.rml` (и что угодно
   ещё) с теми же именами переменных и действий — см. §4. Проверить на
   стенде с крейтом, у которого есть свой файл.
2. RmlUi в игре: HUD и документы крейта (пауза, экраны внутри игры). Хост
   уже живёт весь запуск; нужен контекст «game», ввод из `Game` и API для
   крейта (Lua-плагин RmlUi или свой мост).
3. Друзья: зависит от того, что отдаст дверца лаунчера.
4. Мелочи: галки «творческий режим» / «урон» в одиночной игре
   (`creative_mode`, `enable_damage`, с учётом `disabled_settings` крейта);
   шрифт сайта Golos Text (нужен TTF, в движке только Inter); подсказка
   о переносе клавиш (`dlg_rebind_keys.lua`); вырезать Lua-меню, когда
   решат, что RmlUi покрывает всё.
5. Не переносится намеренно: вкладка содержимого/ContentDB и выбор модов
   для мира — крейт приходит с готовым набором.

**Как проверять:** стенд `axis-assets/tests/menu/xstand.sh` (Xephyr :99,
`click/move/key/type/shot`; `LANG_CODE=en` — английский; `ONLINE=8765` —
поддельные дверца лаунчера и Диспетчер `tests/menu/fake_online.py`, у него
есть `--invite КОМНАТА`, `--refuse-ticket`, `--no-list`). Локальный
выделенный сервер для отклика в списке: `./bin/axis --server --world
worlds/<мир> --port 30077 --config-dir /tmp/axis_srv`.

## 1. Слои

```
client/ui/menu/*.rml *.rcss      вид: разметка и стили, правятся без сборки
src/client/menu/                 логика меню: экраны, модели данных, действия
src/ui/                          хост RmlUi: рендер, ввод, файлы, шрифты
lib/rmlui/                       библиотека как есть
```

`src/ui` знает о RmlUi и Irrlicht и ни о чём больше. `src/client/menu` знает
о меню — мирах, билетах, запуске игры — и не знает о GL. Тема знает только
имена переменных и действий, которые ей отдал экран.

Один `ui::Host` на процесс: RmlUi глобальна. Хост создаёт контексты, грузит
шрифты из `fonts/` (все `.ttf` и `.otf`, `DroidSansFallback*` — как запасной
для недостающих глифов), подтягивает размер окна и масштаб dp перед каждым
кадром и рисует контекст между сценой и `endScene()`.

## 2. Почему логика на C++, а не на Lua

Логика меню — это платформа: билеты, матчмейкинг, presence, друзья. Всё это
HTTP через `httpfetch`, который живёт в C++. Модель данных RmlUi биндится на
C++-структуры напрямую, без слоя копирования. Меню в бинаре — нечего
хэшировать и подменять; `.rml` и `.rcss` без скриптов меняют вид, а не
поведение.

Цена — пересборка при правке логики. Вид, вёрстка, анимации и тексты — файлы,
и перечитываются по F5.

Lua-плагин RmlUi не подключён намеренно: хост о том, кто им управляет, не
знает, и плагин встаёт сверху в тот день, когда крейту понадобится логика в
меню, а не только вид.

## 3. Экран

Экран — документ `<имя>.rml` и модель данных с тем же именем. Класс-наследник
`menu::Screen` в `bind()` вешает на модель переменные и действия; тема
обращается к ним по имени:

```html
<body data-model="worlds">
  <div class="row" data-for="w : worlds" data-event-click="play(it_index)">
    <span class="name">{{ w.name }}</span>
  </div>
  <button data-event-click="nav('start')">[[Back]]</button>
</body>
```

Действия `nav(экран)` и `quit()` есть у каждого экрана. Документ грузится при
первом показе и переживает скрытие; `refresh()` зовётся перед каждым показом
и подтягивает то, что могло измениться.

Текст в документе пишется по-английски в `[[двойных скобках]]` — это ключ
gettext, и переводится он тем же `po/<язык>/axis.po`, что и остальной движок;
`util/updatepo.sh` собирает такие строки сам. Без скобок текст идёт на экран
как есть: RmlUi прогоняет через перевод и то, что подставлено из данных, —
имя мира, значение настройки, — и без метки любое слово, совпавшее с ключом,
уехало бы на другой язык. Текст с подстановкой (`Удалить мир «%s»?`) и
подписи, выбираемые выражением, собираются на C++ через `fmtgettext` /
`strgettext` и отдаются в модель готовой строкой.

## 4. Тема крейта

Меню ищет файлы темы по списку каталогов; сейчас в нём только тема движка.
Каталог крейта встанет первым: крейт кладёт свой `start.rml` — и стартовый
экран его, с теми же действиями и переменными, без строчки C++. Чего крейт
не положил, берётся у движка.

## 5. Рендер

Бэкенд OpenGL 3 взят из поставки RmlUi как есть
(`lib/rmlui/Backends/RmlUi_Renderer_GL3.cpp`). Он написан под глобальные
`gl*`, а движок ходит в GL через загрузчик Irrlicht (`GL.Name`);
`src/ui/gl_loader.h` сводит одно к другому макросами. Шейдеры — GLSL 150:
контекст у движка 3.2 compatibility.

Бэкенд сам сохраняет и возвращает состояние GL вокруг кадра, так что кэш
состояния в драйвере Irrlicht остаётся верным. Слои, фильтры, тени, маски —
всё из RmlUi 6 доступно.

Работает только с драйвером `opengl3`. Без него хост не поднимается, меню
сообщает об этом и закрывается.

## 6. Ввод

`MyEventReceiver` отдаёт события `ui_receiver`, если тот установлен, раньше
меню Irrlicht и игры; что интерфейс поглотил, дальше не идёт. Главное меню
поглощает весь ввод мыши и клавиатуры: под ним никого нет.

Текст с раскладкой и IME приходит строковыми событиями SDL. Устройство
включает их только при фокусе на элементе Irrlicht, поэтому у `IrrlichtDevice`
есть `requestTextInput(area)`: хост зовёт его, когда поле RmlUi берёт фокус.

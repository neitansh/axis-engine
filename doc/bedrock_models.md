# Модели и анимации из Blockbench

Движок читает модели в формате Bedrock — том самом, который Blockbench
выгружает кнопками «Bedrock Geometry» и «Bedrock Animation», а в Minecraft
читает GeckoLib. Файлы берутся как есть: ни конвертации, ни отдельного
инструмента сборки, ни правки JSON руками не требуется.

## Что нужно сделать разработчику

1. **Собрать модель в Blockbench.** Тип проекта — *Bedrock Model*. Кости
   (groups) задают то, что потом можно двигать: у ствола это обычно `gun_body`,
   `magazine`, `bolt`, `trigger`, прицелы.
2. **Нарисовать текстуру** прямо в Blockbench или снаружи; размер полотна
   должен совпадать с `texture_width`/`texture_height` модели.
3. **Сделать анимации** на вкладке *Animate*. Имя анимации — то самое, которым
   её потом запускают из Lua: `idle`, `reload`, `shoot`, `inspect`.
4. **Выгрузить два файла:**
   - `File → Export → Export Bedrock Geometry` → `автомат.geo.json`
   - на вкладке *Animate*: `Animation → Export Animations` → `автомат.animation.json`
5. **Положить в мод:**

   ```
   мод/
     models/
       автомат.geo.json         ← геометрия и кости
       автомат.animation.json   ← все анимации разом
     textures/
       автомат.png
   ```

   Имена файлов до расширения обязаны совпадать: анимации находятся по имени
   модели. Так же они лежат и в модах, откуда обычно берут ассеты.

6. **Использовать в игре:**

   ```lua
   core.register_entity("mymod:rifle", {
       initial_properties = {
           visual = "mesh",
           mesh = "автомат.geo.json",
           textures = { "автомат.png" },
           visual_size = { x = 1, y = 1, z = 1 },
       },
       on_activate = function(self)
           self.object:play_animation("idle", { loop = true })
       end,
   })
   ```

Никакой регистрации модели, загрузки ассетов вручную и особых свойств у
сущности не нужно: `.geo.json` — такой же меш, как `.b3d` или `.gltf`.

## Анимации из Lua

Дорожки зовутся так же, как названы в Blockbench, и работают через обычный
API объектов:

```lua
obj:play_animation("reload", {
    speed = 1,      -- 1 — как задумал автор; 2 — вдвое быстрее; отрицательное — назад
    loop = false,   -- одноразовая анимация
    blend = 0.15,   -- за сколько секунд перетечь из текущей позы
    priority = 10,  -- кто главнее, если дорожек несколько
})

obj:play_animation("idle", { loop = true, priority = 0 })  -- фон под ней

obj:update_animation("reload", { speed = 2 })
obj:stop_animation("reload")   -- без имени — остановить все
obj:get_animations()           -- что сейчас играет
```

Время дорожки считается в секундах, ровно как в файле анимации: `speed = 1`
означает исходную скорость, и переводить кадры ни во что не нужно. Границы
дорожки подставляются сами — `min_frame`/`max_frame` задавать не требуется.

Несколько дорожек играют одновременно: у каждой свой `priority`, и та, что
выше, перебивает нижние **по костям**, которых касается. Это то, ради чего
разделены `idle` и `shoot`: пока верхняя дорожка дёргает затвор, нижняя
продолжает покачивать ствол.

`loop` берётся из вызова, а не из файла: движок не решает за игру, повторять
ли перезарядку. Значения `loop` в самом `.animation.json` (в том числе
`hold_on_last_frame`) при загрузке не читаются.

Кости доступны по именам из Blockbench:

```lua
obj:set_bone_override("magazine", {         -- спрятать магазин
    scale = { vec = vector.zero(), absolute = true },
})
obj:set_attach(other, "muzzle")             -- прицепить вспышку к дулу
```

## Система координат

Всё, что касается осей и единиц, собрано в одном месте —
`src/client/bedrock/convert.h`, — и сводится к двум правилам:

- **Единицы.** Один пиксель Blockbench — это 1/16 ноды. Модель, занимающая в
  Blockbench куб 16×16×16, занимает ровно одну ноду при `visual_size = 1`.
- **Оси.** Переход из Bedrock в движок — поворот на 180° вокруг Y (меняются
  знаки X и Z). Модель, направленная в Blockbench на север, в игре смотрит
  вдоль +Z — туда же, куда смотрит сущность с нулевым поворотом.

Углы в анимациях берутся из файла как есть и применяются в порядке X, Y, Z.
Поворот, заданный кости в модели, — это её поза: анимация к нему
прибавляется, а не заменяет его, как и в Bedrock.

## Что поддерживается

| | |
|---|---|
| геометрия | `format_version` 1.12 и новее (`minecraft:geometry`) |
| кости | иерархия любой глубины, `pivot`, `rotation`, `inflate`, `mirror` |
| кубы | `origin`, `size`, `rotation` вокруг своего `pivot`, `inflate`, `mirror` |
| развёртка | по граням (`uv` объектом), коробкой (`uv` парой чисел), `uv_rotation` |
| грань без `uv` | не рисуется — так в Bedrock прячут невидимые стороны |
| анимации | `format_version` 1.8, каналы `position`, `rotation`, `scale` |
| ключи | по времени, значение одним вектором либо `{"vector": ...}` |
| сглаживание | все кривые Blockbench: sine, quad, cubic, quart, quint, expo, circ, back, elastic, bounce — в трёх видах (In, Out, InOut), плюс `linear` и `step`, с `easingArgs` |
| Molang | арифметика, скобки, `Math.*` (sin, cos, tan, abs, floor, ceil, round, sqrt, exp, ln, pow, min, max, mod, clamp, lerp), `query.anim_time`; углы в градусах |
| несколько файлов геометрии | берётся первая модель в файле |

## Чего пока нет

- **Catmull-Rom** (сглаживание по четырём соседним ключам) считается линейным:
  кривая заявлена в формате, но в анимациях встречается редко.
- **Дорожки событий** — `sound_effects`, `particle_effects`, `timeline` —
  читаются форматом, но никуда не приводят: анимация крутится на клиенте, а
  звуки и частицы в этом движке заводит сервер, и мост между ними — отдельная
  работа.
- **Molang сверх арифметики**: переменные, присваивания, условия и запросы к
  состоянию мира (`query.is_on_ground` и подобные). Неизвестное выражение даёт
  ноль и предупреждение в журнале.
- **`pre`/`post` в ключе** (разрыв значения) — берётся значение после ключа.
- **Локаторы и `binding`** из geo-файла пропускаются.
- **Наборы `item_display_transforms`** (как предмет лежит в руке в Minecraft)
  не читаются: в этом движке предмет в руке устроен иначе.

## Как это устроено внутри

```
Blockbench
   │  Export Bedrock Geometry / Animations
   ▼
автомат.geo.json + автомат.animation.json      ← медиа мода, как текстуры
   │  сервер раздаёт клиенту наравне с прочим
   ▼
GeometryLoader (src/client/bedrock/geometry.cpp)
   │  кости → суставы, кубы → вершины с весом 1 к своей кости,
   │  вся модель в один буфер: одна текстура — один вызов отрисовки
   ▼
scene::SkinnedMesh — обычный скелетный меш движка
   ▲
   │  loadAnimations (src/client/bedrock/animation.cpp)
   │  ключи, сглаживание и Molang запекаются в дорожки при загрузке
   │
автомат.animation.json
   │
   ▼
дорожки по именам → play_animation из Lua → общий рендер и скиннинг
```

Отдельной ветки рендера для этих моделей нет: после загрузки они ничем не
отличаются от `.b3d` и `.gltf`, и всё, что работает для тех, работает и здесь —
прикрепление к костям, переопределение костей, блендинг, аппаратный скиннинг.

### Что сколько стоит

Разбор JSON, сглаживание и Molang считаются **один раз**, при первой загрузке
модели; дальше меш живёт в кеше движка, и вторая сущность с той же моделью не
стоит ничего. Кривые запекаются в ключи с частотой 30 в секунду и только там,
где кривая гнётся: прямые участки остаются двумя ключами. В кадре работает
обычный скиннинг движка — на видеокарте, пока костей не больше, чем позволяет
драйвер, иначе движок сам переходит на расчёт процессором.

Ствол из Just Enough Guns — 25 костей, 159 кубов, 2608 вершин, десять
дорожек — грузится за доли секунды; четыре десятка таких на экране,
проигрывающих пять разных анимаций, идут без заметной просадки.

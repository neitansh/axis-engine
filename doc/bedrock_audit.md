# Аудит переноса трансформаций Blockbench/GeckoLib → движок

Записка для продолжения работы. Здесь только то, что установлено численно,
и то, что осталось непроверенным. Догадки сюда не пишем.

## Установлено

**Поза и геометрия переносятся точно.** Сравнение всех восьми углов куба руки:
положение по формулам GeckoLib против положения по нашему конвейеру, поза
`idle` штурмовой винтовки.

```
right_arm  наибольшее расхождение по углам: 0.0000 ноды
left_arm   наибольшее расхождение по углам: 0.0000 ноды
```

Это покрывает pivot, порядок вращений, знаки осей и наследование от родителя:
ошибка в любом из них развела бы углы. Проверка — офлайн, на Python:
`corners.py` (см. ниже, где взять).

**Blockbench показывает эти модели зеркально игре.** В файле кость `right_arm`
лежит при отрицательном X:

```
в файле (Bedrock):     right_arm  X от −7.50 до −4.50
                       left_arm   X от +4.50 до +7.50
после конверсии:       right_arm  справа, left_arm слева  (как в Minecraft)
```

Зеркало по X — часть формата: GeckoLib применяет его при загрузке
(`BakedModelFactory.constructCube`: `origin.x → −(origin.x + size.x)`).
Отсюда правило: **сравнивать нашу картинку с окном Blockbench нельзя**, они и
должны быть зеркальны. Эталон — игра с модом, а не редактор.

**Дорожка `draw` (gun_body, канал rotation).** Ключи по Z:
`0 → 69 → 96 → 99 → 0` градусов; через половину оборота не переваливают.
Значит расхождение в этой анимации не объясняется кратчайшей дугой между
поворотами.

## Не проверено — отсюда продолжать

Все сравнения выше — это **наша реализация формул против GeckoLib на бумаге**.
Не проверено главное звено: делает ли фактический код движка то же самое.
Между задумкой и экраном стоят:

- `core::Transform::buildMatrix` — фактический порядок T·R·S;
- `SkinnedMesh::calculateGlobalMatrices` — порядок `parent × local`;
- `GlobalInversedMatrix` (bind-поза), которую задаёт наш загрузчик;
- `Channel<quaternion>::get` — slerp между ключами;
- `animateMesh` — приоритеты дорожек и смешивание.

Нужный тест: заставить движок распечатать глобальные матрицы суставов для
заданной модели, дорожки и момента времени и сравнить покадрово с эталонным
расчётом. Пока этого нет, любые выводы о «правильности» рантайма
преждевременны.

## Чем пользоваться

- `tests/bedrock/shoot.sh` — стенд: сам достаёт ассеты из мода и снимает кадр.
- `games/salvo/util/guns_from_jeg.sh` — готовит стволы для salvo из того же мода.
- Эталонный расчёт (Python, без зависимостей) и декомпилированные
  `GunRenderingHandler`, `AnimatedGunRenderer` лежали в каталоге сессии
  (`.../scratchpad/`): при новой сессии проще пересоздать — декомпиляция
  делается Vineflower, java в системе уже есть.

## Известные расхождения, не объяснённые численно

- Поза левой руки в игре против игры с модом (не против Blockbench!).
- Направление поворота оружия в `draw`.

Оба нуждаются в сравнении рантайма с эталоном по матрицам, а не по кадрам.
